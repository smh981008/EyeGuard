# 视线守卫 (EyeGuard)

Windows 桌面小工具：用摄像头盯着你。**当你把脸 / 视线从屏幕上移开，自动黑屏、切换窗口、锁屏或息屏。**

纯本地运行，不联网、不写盘、不上传画面。

---

## 快速开始

直接双击 `启动.bat`。它优先启动已打包的 `dist\EyeGuard\EyeGuard.exe`，
没有打包版时才用 `pythonw app.py` 跑源码。

从源码跑：

```bash
pip install -r requirements.txt
python app.py
```

启动后右下角托盘出现一个眼睛图标（绿=在座位，红=已离开，灰=暂停），同时弹出设置窗口。

## 它怎么判断"你走了"

不是"画面里有人脸就算在位"——那样趴桌上睡觉也算在位。实际用了四路信号：

| 信号 | 含义 | 默认 |
|---|---|---|
| 画面中没有人脸 | 直接算离开（人走开 / 转得太厉害检测不到） | 开 |
| 人脸宽度占画面比例 < 12% | 人坐远了 / 起身了 | 开 |
| 读不出脸部朝向 > 5 秒 | 已经侧到看不清正面，或被挡住 | 开 |
| 头部转开 > 65°，或抬头低头 > 55° | 转头看别处 | **关** |
| 人脸中心偏离画面中心 | 人侧身挪出视野 | 关 |

外加一道**键鼠活动闸门**：只要最近 8 秒内有键盘/鼠标输入，就绝不判定离开。

### 为什么"头部转开"默认是关的

5 个关键点只能测"脸对着哪"，测不出"眼睛在看哪"。而你**看副屏、看手机、低头看键盘**
时，头本来就会偏 30~60°，和"人已经走了"在几何上完全一样。开启这一项，就会在你正常
办公时随机黑屏。

所以默认只判断"人在不在座位"：人脸还在、尺寸正常，就算在位。真要走，人脸会先离开
画面；转得太狠时关键点会读不出来，2.5 秒后照样会黑屏。

需要"视线一移开就黑屏"的激进行为时，勾选这一项并把角度调到 35~45°，接受它偶尔误判。

### 两个曾经把体验毁掉的坑

**1. "看不清"曾被当成"在位"。** 侧脸时 YuNet 仍会返回人脸框，但关键点已经乱了，程序
读不出朝向。旧逻辑把这种帧当成"没有触发原因"，于是恢复计时一路累加——人明明还转着
头，0.2 秒后屏幕自己亮了。现在这类帧既不算在位、也不立刻算离开，而是保持当前状态；
只有真的看到正面并持续一小段时间，才允许恢复。

**2. 角度换算在大角度会饱和。** 鼻尖偏移量除以眼距后按 `atan` 换算，超过 55° 后这个
比值不再随角度增长（侧脸时鼻尖已经跑到脸边缘），所以"阈值 55°"实际上永远触发不了，
真正转开时反而测出来只有 45°。现在侧脸检测改由"关键点读不出来"兜底，不再依赖角度
数值本身。

### 键鼠活动闸门

摄像头只能看到"脸朝哪"，看不到"你在不在用电脑"。而**键盘鼠标输入是比任何视觉特征都
硬的证据**：手在动，人就没走。

- 它只做**否决**：正在用电脑时不判离开（防误黑屏）
- 它**不会**把已经黑掉的屏幕点亮——那样你转头动一下鼠标屏幕就亮，又回到老问题
- 人脸彻底消失超过 8 秒后，这道闸门失效（人走了但后台有程序在模拟输入的情况）

### 头部朝向怎么算的（以及为什么不用 solvePnP）

YuNet 只给 5 个关键点：双眼、鼻尖、左右嘴角。常见的做法是套一个通用 3D 人脸模型做
`solvePnP` 解姿态，但**这 5 个点在真实人脸上近似共面**，姿态存在镜像二义性。实测侧脸
超过约 40° 时，`solvePnP` 会稳定地收敛到"人脸倒转 180°"的解（pitch/roll 跳到 ±165°），
EPNP、SQPNP、带初值的 ITERATIVE 三种解法结果一致——说明不是数值问题，是这组点本身
就支持两个解。

所以这里改用**几何直测**：

- **翻滚角 roll** = 双眼连线的倾角，最可靠，不依赖任何假设
- **左右转 yaw** = 鼻尖相对双眼中点的水平偏移 ÷ 眼距，再按 `atan` 换算成角度
- **俯仰 pitch** = 鼻尖相对双眼中点的垂直偏移 ÷ 眼距（先按 `cos(yaw)` 补偿转头导致的
  眼距透视压缩）

所有量都除以眼距做归一化，所以**跟距离、分辨率、摄像头焦距都无关**，也不存在解翻转。
用符合真实人脸比例的模型生成投影数据验证过：yaw 误差 < 2°，正脸低头误差 < 3°。

代价是需要一个"零点"。默认假设是**鼻尖正好在双眼中点的正下方**（水平偏移 0、
垂直偏移 0.65 个眼距），这对绝大多数摄像头都成立。

### 什么时候需要校准

摄像头装在屏幕下沿、仰角很大，或者你习惯性斜坐时，"正对屏幕"在画面里本来就不是 0°。
判断方法：打开**实时预览**，正对屏幕坐好，看角度是不是接近 0。

- 接近 0 → 不用校准
- 明显偏（比如 yaw 一直显示 -30°）→ 保持这个坐姿点一次 **校准当前姿态为基准**

程序**不会自动学习基准**，这是刻意的：机器无法分辨"正对屏幕"和"扭头看副屏"。
一旦把看副屏的姿势自动学成基准，你真正正对屏幕时反而会被判成转开，比不校准更糟。

### 用副屏办公

默认配置就是为这种场景准备的：头部偏转关着，只按"人在不在"判断，看副屏不会黑屏。
如果你后来自己打开了"头部明显转开"，记得把角度阈值定在 65° 以上，或者再关掉它。

### 时间防抖

避免"低头喝口水就黑屏"：

- 离开必须**持续** `leave_delay` 秒（默认 2.5 秒）才触发
- 回来必须**持续** `return_delay` 秒（默认 1 秒）才恢复
- 阈值附近有回差：进入用严格阈值，退出用宽松阈值（0.6 倍），不会在临界点一亮一灭

预览页能看到实时角度、人脸占比、键鼠空闲时长和判定原因，方便对着数字调阈值。

### 黑屏期间到底发生了什么

状态是"离开"时，程序每 1.5 秒检查一次遮罩是否还在最前面。Windows 上任何新出现的置顶
窗口（播放器、通知横幅、游戏、远程桌面）都能盖住遮罩，看起来就是"人明明不在，屏幕却
自己亮了"，而检测其实一切正常。看门狗会把遮罩重新提到最上层。

按 ESC 手动关掉遮罩后，这一轮不会再自动弹回来，直到你回来一次再离开。

### 怎么解除黑屏

黑屏期间**按任意键、点一下鼠标、或者把鼠标挪动十几像素**，遮罩立刻消失——不用去找 ESC。

检测走的是 Windows 的全局键鼠状态（`GetAsyncKeyState` / `GetCursorPos`），不依赖窗口焦点。
这点很关键：遮罩是一块置顶窗口，Windows 随时可能把焦点交给别的置顶窗口、输入法候选框、
游戏或远程桌面，靠窗口收键盘事件的方案在那些时候会"按了没反应"。

两个细节：

- 记的是**基线**而不是"现在有没有输入"。黑屏弹出时你正按着 Shift、手还搭在鼠标上，都不
  会立刻把遮罩掀开；只有"新按下一个键"或"光标明显移动"才算。
- 黑屏最初 250 毫秒内的输入会被吞掉，避免遮罩刚出现就被自己的动画/焦点变化关掉。

如果你希望"起身时不小心碰到鼠标"不至于让整段离开都失去保护，把设置里的
**「解除后多久没操作、人仍不在就重新黑屏」** 设成 20~30 秒即可（默认关闭）。

想恢复成只能用 ESC，取消勾选「按任意键 / 移动鼠标即可解除」。

## 触发动作

可多选：

- **黑屏遮罩** — 全屏纯黑置顶窗口，覆盖所有显示器，淡入出现，回来自动消失。不影响任何
  程序运行，是推荐方案。按任意键 / 动鼠标 / ESC 都能手动关闭（防止意外被困）。
- **切换窗口** — Alt+Tab
- **显示桌面** — Win+D，最小化所有窗口
- **锁定电脑** — 系统锁屏
- **关闭显示器** — 真正息屏（省电），但需要手动动一下鼠标 / 键盘唤醒

## 定时计划

只想在上班时间盯人，下班和周末别管你？设置 → **定时计划**：

- 勾选「只在下面设定的时间里运行检测」
- 设开始 / 结束时间，`22:00` 到 `06:00` 这种跨夜写法直接支持
- 选星期，**每天 / 工作日 / 周末** 有快捷按钮

到点自动启停，程序本身一直待在托盘里，不需要退出。

几条边界规则，都是踩过的坑：

- **只在跨越时段边界时动作**。你在时段外手动点了「启用检测」想临时用一下，不会被 20 秒后
  的轮询推翻，一直到下一个时间边界才交回计划。
- **跨午夜的时段按开始那天算星期**。勾了周一 + 22:00~06:00，周一 22:00 到周二 06:00
  都在时段内，周二晚上 22:00 不算。
- 一天都不勾等于「每天」。为了不让这个歧义把人绕进去，取消最后一个勾选时会自动恢复全选。
- 时间填坏了（比如 25:70）按「全天」处理 —— 宁可不管，也不会把软件锁成永远不运行。

页面里直接显示当前状态：「现在在计划时段内…检测会正常运行」/「现在不在…检测已自动暂停」，
右下角徽章也会变成「计划外暂停」。

## 上班鼓励器

黑屏的时候屏幕全黑，光看着挺浪费 —— 顺便把今天的工资打在正中间。设置 → **上班鼓励器**：

- 填 **月薪**、**每月计薪天数**、**上下班时间**、**工作日**
- 黑屏上显示：今日已赚（每秒往上爬）、时薪、每分钟赚多少、今日进度条、距下班还有多久

换算口径：

```
日薪 = 月薪 ÷ 每月计薪天数        （5 天工作制填 21.75，单休约 26）
时薪 = 日薪 ÷ 每日在岗小时        （= 下班时间 - 上班时间）
今日已赚 = 日薪 × 已经过去的比例
```

几点说明：

- **钱是按秒连续折算的**，不做整点跳变，所以盯着看能看到数字在涨。
- **午休算在在岗时段里**。这样「今天赚了多少」= 「你在工位上坐了多久」，符合直觉；
  想按实际工时算，把上班时间往后调（09:00 改成 10:00）或缩短每天区间即可。
- **跨夜班次支持**：22:00 到 06:00 这种，周二凌晨 2 点算的是「周一那班」，进度和余额都接着算。
- 不是工作日、还没到点、已经下班，都会给出对应文案（「今天休息 · 明天继续」），不会显示成
  一个假数字。
- 月薪留空就完全不显示，黑屏还是原来的纯文字样子。升级到这一版时，上班时间会自动继承
  「定时计划」里的时段，不用重新填一遍。

## 参数怎么调

全部在设置窗口里，改完即时生效，点"保存设置"写入 `config.json`。

- **太敏感**（老误触发）：先确认"正在敲键盘/动鼠标时不判定离开"是开着的；再把
  `leave_delay` 调大（3~5 秒），或关掉"人脸太小"这一项
- **不灵敏**（走了没反应）：调小 `leave_delay`；只在转头时才想黑屏，就勾上"头部明显
  转开"并把角度调到 35~45°

先用实时预览看自己平时的数值，再定阈值，比盲调快得多。预览页还会显示"键鼠空闲 X 秒"，
能直接看出活动闸门有没有在起作用。

> 旧版本的配置里如果 `yaw_threshold` 被拖到 10° 这类极端值，升级后会自动拉回安全范围，
> 并关掉"头部明显转开"。不需要手动改 `config.json`。

## 项目结构

```
app.py                 入口：Qt 主循环、信号桥、托盘 / 遮罩 / 设置窗口装配
core/config.py         配置读写、资源路径
core/vision.py         几何法头部朝向测量（无 PnP）
core/detector.py       摄像头线程、人脸检测、在位/离开状态机、基准校准
core/activity.py       键鼠空闲时长（活动闸门用，直接调 Win32）
core/schedule.py       定时计划：星期 + 时间段判定（含跨午夜）
core/payroll.py        上班鼓励器：时薪换算、今日进度、距下班
core/wake.py           黑屏期间的全局键鼠唤醒检测
core/actions.py        模拟按键、锁屏、息屏、开机自启、多屏坐标
ui/settings.py         设置窗口（五页：触发动作 / 判定规则 / 定时计划 / 上班鼓励器 / 实时预览）
ui/overlay.py          全屏黑屏遮罩
ui/tray.py             托盘图标
ui/theme.py            配色与样式表
models/                YuNet 人脸检测模型（232KB）
assets/                图标
```

两个线程：主线程跑 Qt（界面 + 遮罩 + 托盘），`detector` 线程读摄像头做检测。
跨线程只走 Qt 信号（自动排队到主线程），不做共享状态 hack。

依赖：PySide6-Essentials、opencv-python、numpy。**不需要 tkinter**（很多精简版 Python 没有）。

## 打包成 exe

```bash
pip install pyinstaller
python -m PyInstaller --noconfirm --clean --windowed --name EyeGuard ^
  --icon assets/icon.ico ^
  --add-data "models/face_detection_yunet_2023mar.onnx;models" ^
  --exclude-module tkinter ^
  app.py
```

产物在 `dist/EyeGuard/`，整个文件夹拷走就能用，不需要装 Python。
配置写在 exe 同级的 `config.json`。

托盘菜单勾选 **开机自动启动** 会写入注册表
`HKCU\Software\Microsoft\Windows\CurrentVersion\Run`，不需要管理员权限。

## 发一个版本

版本号写在 `core/config.py` 的 `APP_VERSION`，改完用 `EyeGuard.spec` 打包，再把 `dist/EyeGuard`
压成带版本号的 zip 传到 GitHub Release：

```bash
python -m PyInstaller EyeGuard.spec --noconfirm --distpath dist --workpath build
```

压缩包格式为 `EyeGuard-v<版本>-win64.zip`，内含 `EyeGuard/` 目录（`EyeGuard.exe`、`_internal/`、
`使用说明.md`），**不打包 `config.json`** —— 那是本机的校准值和阈值，不该发给别人，也让首次
启动能走默认参数并提示校准。

已有版本见 [Releases](https://github.com/smh981008/EyeGuard/releases)。

## 已知限制

- **摄像头被独占**：Windows 上多数摄像头不支持共享，被其他程序占着就打不开。关掉占用程序即可。
  程序会自动重试，不会崩。
- **强逆光 / 极暗**：人脸检测失效，表现为"一直判定离开"。
- **戴墨镜、口罩、手挡脸**：关键点会退化。程序加了关键点几何合理性检查，读不出朝向
  时保持当前状态，持续 5 秒以上才算离开（不会因为一帧读不出就误判，也不会因为
  手撑着脸 2 秒就黑屏）。
- **接近 90° 的侧脸**：YuNet 基本检不到人脸，会走"画面中没有人脸"分支；检到了但关键点
  已经不可用的，走"读不出朝向"分支。两条路都会黑屏。
- **看副屏 / 低头看键盘**：和"人转开了"在几何上无法区分，所以默认不用头部角度做判断。
- **背景误检**：画面里的小图案（海报、贴纸、显示器上的图片）可能被误检成人脸，程序会
  丢弃小于 36px、置信度低于 0.68 的框。
